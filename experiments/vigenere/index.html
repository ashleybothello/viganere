📖 Introduction & Aim

Aim

To implement the Vigenère cipher for encryption and decryption, and to observe, through frequency analysis, how a polyalphabetic substitution resists the attacks that easily break a simple monoalphabetic cipher.

Introduction

The Vigenère cipher is a method of encrypting alphabetic text using a simple form of polyalphabetic substitution. Unlike a monoalphabetic cipher such as Caesar — which applies a single, fixed shift to every letter — the Vigenère cipher uses a keyword to select a different shift for each position in the plaintext.

The technique was first described by Giovan Battista Bellaso in 1553, but was later misattributed to Blaise de Vigenère, whose name became permanently associated with it. For roughly three centuries the cipher was regarded as unbreakable, earning the French epithet "le chiffre indéchiffrable".

In 1863, Friedrich Kasiski published a general method for breaking the Vigenère cipher by exploiting the periodic repetition of the keyword. Today, the cipher is understood to be insecure for serious use, but it remains an excellent pedagogical tool for understanding the principles of polyalphabetic substitution, modular arithmetic in cryptography, and the fundamentals of cryptanalysis.

Monoalphabetic vs. Polyalphabetic

A monoalphabetic cipher (e.g., Caesar) uses a single substitution alphabet — every occurrence of a given letter is always replaced by the same ciphertext letter. This makes the cipher vulnerable to frequency analysis: the most common ciphertext letter likely corresponds to the most common plaintext letter (typically 'E' in English).

A polyalphabetic cipher uses multiple substitution alphabets, cycling through them. In the Vigenère cipher, each letter of the keyword defines a different Caesar shift. The same plaintext letter can therefore be encrypted to different ciphertext letters at different positions, disrupting the simple one-to-one letter mapping that frequency analysis relies on.

Mathematical Formulation

Assign each letter a numeric value: A = 0, B = 1, C = 2, …, Z = 25.

Let:

  • Pi — numeric value of the i-th plaintext letter
  • Ki mod m — numeric value of the corresponding key letter (key repeats with period m)
  • Ci — numeric value of the resulting ciphertext letter

Encryption Formula

Ci = ( Pi + Ki mod m ) mod 26

Decryption Formula

Pi = ( Ci − Ki mod m + 26 ) mod 26

The "+26" in the decryption formula ensures the intermediate value is non-negative before the modulo operation.

Important Observations

  • Key length 1 reduces the Vigenère cipher to a simple Caesar cipher (a single shift applied to every letter).
  • A key letter of 'A' (value 0) means no shift at that position — the plaintext letter passes through unchanged.
  • A random key as long as the message and never reused produces a one-time pad, which is theoretically unbreakable.
  • In practice, Vigenère keys repeat, which creates structural weakness exploitable by Kasiski examination and the index of coincidence.
  • For a keyword of length m, there are 26m possible keys. For m = 5: 265 = 11,881,376 possible keys.

Tabula Recta (Vigenère Square)

The tabula recta is a 26×26 grid where row r, column c contains the letter at position (r + c) mod 26. To encrypt: find the column headed by the plaintext letter and the row headed by the key letter; the intersection is the ciphertext letter.

⚙️ How Vigenère Works

Working Principle

  1. Assign each letter a numeric value: A = 0, B = 1, …, Z = 25.
  2. Write the keyword beneath the plaintext, repeating it as needed. Non-alphabetic characters in the plaintext are skipped (the key does not advance).
  3. Encryption: For each alphabetic position, add the plaintext value and the key value, then take mod 26.
  4. Decryption: For each alphabetic position, subtract the key value from the ciphertext value, add 26, then take mod 26.
  5. Convert the resulting numeric value back to a letter. Preserve the original case of the plaintext/ciphertext character.

Key Alignment Example

For plaintext ATTACK AT DAWN and key LEMON:

Plaintext: A T T A C K   A T   D A W N
Key: L E M O N L   E M   O N L E
Ciphertext: L X F O P V   E F   R N H R
Note: The spaces in the plaintext pass through unchanged, and the key does not advance at those positions. The key letter after K (at "ATTACK") continues as E (at "A" in "AT"), not restarting.

Edge Cases & Validation Rules

  • Empty key → Rejected with an error message.
  • Key containing symbols/numbers → Non-letter characters are removed; if no letters remain, the key is rejected.
  • Key shorter than plaintext → Key repeats cyclically.
  • Key longer than plaintext → Only the required key characters are consumed.
  • Single-character key → Behaves as a Caesar shift.
  • Non-alphabetic plaintext characters → Preserved in output; do not advance the key pointer.
  • Case → The original upper/lower case of each plaintext letter is preserved in the ciphertext.

📊 Cryptanalysis — Frequency Analysis

About Frequency Analysis

Frequency analysis counts how often each letter (A–Z) appears in a text and calculates its percentage of all alphabetic characters. In English, certain letters (E, T, A, O, I, N, S, H, R) appear far more frequently than others.

A monoalphabetic cipher like Caesar preserves this distribution — the ciphertext histogram is simply a shifted copy of the plaintext histogram. This makes it trivially breakable.

The Vigenère cipher uses multiple shifts (one per key letter), so the same plaintext letter can map to different ciphertext letters. This flattens the ciphertext frequency distribution, making single-letter frequency analysis less effective. However, because the key repeats, structural patterns remain — methods such as Kasiski examination and the index of coincidence can exploit this repetition.
